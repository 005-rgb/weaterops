## Konfigurasi database
1. Setup koneksi PostgreSQL via environment variable `DATABASE_URL`.
2. Buat `src/infrastructure/database/client.ts` — koneksi pool (gunakan `pg` +
   query builder ringan seperti `Kysely` ATAU raw `pg` dengan migration tool
   terpisah seperti `node-pg-migrate` — pilih SATU, dokumentasikan pilihanmu di
   `docs/adr/0001-database-tooling.md`, jangan campur beberapa tool migrasi).
3. Buat `src/infrastructure/database/migrations/` — folder migration, KOSONGKAN
   untuk saat ini (migration tabel dikerjakan di Fase 1, JANGAN buat tabel apa pun
   di fase ini).
4. Jalankan `CREATE EXTENSION IF NOT EXISTS postgis;` sebagai migration paling awal
   (migration 0000) — ini SATU-SATUNYA migration yang boleh kamu buat di fase ini,
   karena PostGIS harus aktif sebelum fase manapun berikutnya jalan.
5. Verifikasi ekstensi aktif dengan query `SELECT PostGIS_Version();` dan tampilkan
   hasilnya di log startup.

## Environment & config
- Buat `.env.example` berisi semua variable yang akan dipakai proyek ini secara
  keseluruhan (boleh mendaftarkan variable yang baru dipakai di fase-fase
  berikutnya, dengan komentar fase mana yang memakainya), minimal:
  DATABASE_URL=
  NODE_ENV=development
  PORT=3000
  # Fase 2 — BMKG
  BMKG_BASE_URL=
  BMKG_RATE_LIMIT_PER_MIN=
  # Fase 8 — anti-abuse
  TURNSTILE_SECRET_KEY=
  # Fase 9 — tracing
  OTEL_EXPORTER_OTLP_ENDPOINT=
- Buat `src/app/config/env.ts` yang memvalidasi environment variable memakai
  `zod` (fail-fast saat startup jika variable wajib untuk fase-fase yang SUDAH
  aktif tidak ada — tapi jangan wajibkan variable fase yang belum dikerjakan).

## Middleware dasar (skeleton saja, isi minimal)
- `src/app/middleware/error-handler.ts` — global error handler Express yang
  mengembalikan bentuk error JSON konsisten:
  { "error": { "code": "STRING_CODE", "message": "string" } }
  (Kode error konkret didaftarkan bertahap di fase-fase berikutnya — untuk fase
  ini cukup buat SATU kode generik `INTERNAL_ERROR`.)
- `src/app/middleware/request-logger.ts` — log setiap request (method, path,
  status, durasi ms) dalam format JSON terstruktur ke stdout (bukan file, karena
  Replit environment; format ini akan diperluas Fase 9 dengan trace_id).
- JANGAN buat middleware i18n, anti-abuse, atau tracing sungguhan di fase ini —
  cukup buat file kosong dengan komentar penanda fase seperti pola README di atas.

## Endpoint yang WAJIB ada di fase ini (dan HANYA ini)
GET /api/v1/system/health
  -> 200 { "status": "ok", "database": "connected", "postgis": "<versi>", "timestamp": "<ISO>" }
  Jika database tidak terkoneksi -> 503 { "status": "degraded", "database": "disconnected" }

## Testing
- Setup test runner: `vitest` (jangan Jest, agar konsisten dengan ESM + TS modern).
- Tulis test untuk:
  1. Health check mengembalikan 200 saat DB terkoneksi.
  2. Health check mengembalikan 503 saat DB terputus (mock koneksi gagal).
  3. Environment validator menolak startup jika DATABASE_URL kosong.
- Tambahkan script `npm test`, `npm run test:watch` di package.json.

## Linting & formatting
- ESLint + Prettier, konfigurasi TypeScript strict.
- Tambahkan `npm run lint` dan `npm run typecheck` (tsc --noEmit) di package.json.
- Tambahkan pre-commit tidak wajib (skip husky, ini bukan prioritas Fase 0).
